# NeuroCube engineering rules

Read [README](README.md), [product vision](docs/product-vision.md), [documentation policy](docs/documentation-policy.md), [architecture](docs/architecture.md), [hardware](docs/hardware.md), then [progress](docs/progress.md) and [backlog](docs/backlog.md). Read the task explicitly assigned by the user; historical task files are not the sole long-term requirements source. Do not treat planned features as implemented.

Use C++17 and Clean Architecture. Domain defines values and ports; application coordinates lifecycle/input; games have no hardware dependencies; infrastructure alone imports Pico SDK. Native and firmware builds share core sources. Prefer small interfaces and static registration. Preserve agreed gameplay, personalization and paired Magic Ball texts unless the user explicitly changes them.

Run native tests before firmware integration. Report VERIFIED_ON_HARDWARE, VERIFIED_IN_SIMULATOR, COMPILED_ONLY or NOT_TESTED with evidence. Distinguish physical user checks, synthetic hardware input, USB telemetry and framebuffer captures. Do not infer battery, visual or touch acceptance from enumeration.

Target only Waveshare RP2350-Touch-LCD-1.54. Verify the exact schematic/examples before changing pins; follow [hardware](docs/hardware.md). Keep battery latch GPIO28 HIGH during normal operation; the explicitly requested PWR shutdown alone may release it after successful save, LCD presentation acknowledgement, one second of visibility and PWR release. Never flash shutdown-capable firmware without the task-specific explicit permission; GPIO24/17/29 diagnostics are read-only. Never use RESET as a game button or change charger, OTP, security settings or OS protections. Flash/reset only an explicitly authorized, identity-matched device; preserve records and backups. Existing user authorization persists across turns. Never commit credentials, factory backups or build binaries.

Keep work on codex/neurocube-mvp; preserve uncommitted changes when syncing, push incremental commits and update the existing PR. Do not force push or merge main.

For every functional change, update the relevant backlog status, progress evidence and CHANGELOG entry. Update player/build/bridge instructions when behavior changes. Change README/vision only for deliberate strategic decisions. New games affect vision when the catalog changes, architecture when the contract changes and CHANGELOG after implementation. Follow the document responsibility table; link instead of duplicating. Run `python docs/tools/check_docs.py` after documentation edits. Preserve historical observations and mark their scope; never claim closure solely because a commit exists.

Release work: original code is MIT; preserve third-party file-level licenses and THIRD_PARTY_LICENSES.md. Audit history and artifacts without logging secret values. Do not rewrite history, change visibility, merge, flash or publish a stable release without the corresponding explicit authorization. A licensing/readiness blocker is not removed by user approval alone. Keep 1.0 gameplay frozen to the 0.3.5 baseline; version/build/documentation changes must not modify records or hardware behavior. The explicit replace-es8311-driver-license task authorizes only an Apache-2.0 codec/transport adaptation; preserve PIO/DMA, NS4150B sequencing, gain60 and the explicitly requested PCM2560 (+100% from PCM1280; user accepted sound in installed f6c60d7) and all other hardware behavior. Do not reintroduce retired restricted driver or loud RAM probe; see third_party/espressif_es8311/provenance.json.

The explicit post-1.0 request authorizes shutdown-screen copyright "© 2026, мальчик Коля + OpenAI" and the missing OFL © glyph for 1.0.1. Keep PWR/save/power-cut timing unchanged; reviewed UI-only freeze hashes are in tools/release-freeze-1.0.1.json. Do not overwrite published 1.0.0 assets or tag.
