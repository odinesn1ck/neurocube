# NeuroCube — плавное ускорение показа Simon («Повтори ритм»)

## Цель
Добавить постепенное ускорение **только демонстрации** последовательности по мере роста раунда (длины последовательности). Не ускорять и не ограничивать по времени ввод игрока. Сохранить узнаваемую механику Simon, читаемые фазы, яркое выделение активной фигуры и управление наклонами/сенсором.

## Текущее поведение (проверить по HEAD)
В `SequenceGame::start()` начальный `step = 1.4f - int(d) * .18f`: Easy 1.40, Normal 1.22, Hard 1.04 с/сигнал. `SequenceGame::update()` использует постоянный `step` для Showing; длина увеличивается до 32. Значение не пересчитывается при новом раунде. Сложность влияет на начальную скорость, а не на прогрессию.

## Требуемое поведение
1. Сохранить начальные длительности Easy=1.40, Normal=1.22, Hard=1.04 секунды на сигнал, если не выявлено обоснованных UX-проблем.
2. С каждым завершённым раундом плавно уменьшать время на один сигнал; без резких скачков и без ускорения внутри одного показа. Рекомендация — линейная или сглаженная функция от `length` с параметрами в одном месте, без magic numbers.
3. Для Normal ориентир: 1-й раунд 1.22 с, 5-й ~1.12, 10-й ~1.00, 15-й ~0.88, 20-й ~0.76, 25-й ~0.64, 32-й ~0.50 с. Это ориентиры UX, а не требование совпасть до сотых. Для Easy/Hard аналогичное плавное ускорение с разумными нижними пределами, не ниже 0.50 с на сигнал без отдельной физической приёмки.
4. Сохранять заметный интервал погасания между сигналами (сейчас активная фигура показывается 65% `step`); при ускорении сигнал всё ещё должен быть визуально различим.
5. Фаза Recall остаётся без таймера на ввод, текущая пауза/подсветка успешного действия и 3–2–1 перед началом сохраняются. Никаких новых штрафов за медленный ответ.
6. На каждом раунде повторно демонстрируется вся последовательность с одинаковым `step` для всех её элементов. При переходе к следующему раунду пересчитывается длительность.
7. Перезапуск возвращает начальную скорость, соответствующую выбранной сложности; пауза/возобновление не сбрасывают прогрессию; результаты и рекорды сохраняются как прежде.

## Архитектура и ограничения
- Соблюдать Clean Architecture: расчёт длительности — чистая функция domain/game, без Pico SDK, GPIO и зависимости от UI.
- Не менять каталог игр, Magic Ball, «Привет, Андрей», QR, скринсейвер, выключение PWR, аудио HAL и формат flash журнала.
- Если параллельно ведётся разработка аудио, аккуратно интегрировать изменения без перезаписи незакоммиченного кода.

## Тесты
- Native: монотонное невозрастание `step` от раунда 1 к 32 для каждой сложности; точная начальная скорость; нижняя граница; отсутствие скачков на границах; сброс при restart.
- Для каждого раунда: Showing/Recall/Correct/Failure, корректное количество показанных сигналов, один и тот же `step` внутри раунда, сохранение префикса, детерминизм seed.
- Доказать тестом, что ввод игрока не имеет нового тайм-аута: длительная задержка в Recall не приводит к проигрышу.
- Проверить рендер активной фигуры на поздних быстрых раундах, native suite, Windows simulator, RP2350 UF2, CI.
- На реальном LCD удобство восприятия поздних раундов остаётся NOT_TESTED до подтверждения пользователя.
