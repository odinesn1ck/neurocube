# NeuroCube — тихие игровые звуки и единый переключатель

## Основание
Пользователь подтвердил: встроенный звук на имеющейся Waveshare RP2350-Touch-LCD-1.54 **работает**, но тестовый писк был **очень громким**. Никаких аппаратных доработок. Цель — два ненавязчивых звуковых эффекта и глобальная сохраняемая настройка звука.

## Перед реализацией
Прочитать AGENTS.md, docs/architecture.md, docs/hardware.md, docs/backlog.md, docs/progress.md, docs/player-guide.md; найти отчёт о тестовом звуке, фактически использованный GPIO/драйвер/частоту/duty и официальную схему. Не угадывать пины, не использовать нештатные способы звукоизвлечения. Убедиться, что тестовый аудиодрайвер не конфликтует с GPIO13 подсветки, BAT_EN GPIO28, LCD, touch, IMU, PWR и PLUS. Если тестовый код/доказательства отсутствуют — сначала read-only анализ и безопасная диагностика.

## Эффекты
- **Ошибка игры**: короткий приглушённый «кх», мягкий нисходящий/сухой тон, ориентир 80–140 мс. Только при фактическом переходе в ошибку/проигрыш; не воспроизводить каждый кадр или при каждом контакте со стеной, если это не ошибка.
- **Новый ответ Magic Ball**: мягкий округлый «уоп» длительностью примерно 120–220 мс, с небольшим изменением частоты. Один раз при принятом запросе ответа (включая shake с правил), не при каждой фазе анимации и не при отклонённом повторном запросе.
- Не добавлять пока звуки навигации, наклонов, обычных касаний, правильных ответов, скринсейвера, splash и выключения.
- Оба эффекта синтезировать штатным аппаратным выходом, без аудиофайлов при возможности; неблокирующий event-driven playback, один голос, корректное завершение и silence на shutdown.

## Громкость — критический критерий
Тестовый писк был слишком громким. Начинать с **очень низкой интенсивности**, заведомо намного тише теста; не воспроизводить максимальный писк снова. Снижать PWM duty/амплитуду только способом, который реально уменьшает акустическую громкость данного звукоизлучателя (учесть пассивный/активный тип и резонанс). Не считать числовой duty прямой мерой dB. Сначала проверить на низком уровне и попросить пользователя оценить фактическую громкость. Если программное снижение неэффективно, не включать громкий звук в релиз: оставить выключенным по умолчанию или неактивным до решения, без аппаратных доработок. Не допускать длинных/непрерывных сигналов и наложений.

## UI
На каждом экране «Как играть» (Rules) разместить понятную и доступную сенсорную пиктограмму **звук включён / звук выключен**. На 240×240 hitbox достаточный и не перекрывает текст, кнопки «Играть», глобальную навигацию и область старта встряхиванием. Первое касание пиктограммы только меняет звук, НЕ запускает игру и не запрашивает ответ шара. Внешний вид отражает текущее общее состояние. Одна настройка для Simon, Maze, Commands и Magic Ball; при переключении игр состояние не сбрасывается. По умолчанию — звук выключен до физического подтверждения безопасной громкости; после подтверждения пользователь может включать.

## Сохранение
Настройка sound_enabled сохраняется в общем RecordStore и восстанавливается при холодном запуске. Существующий формат v3, оба сектора flash, sequence, рекорды, чувствительность и калибровка должны сохраниться. Изучить возможность использовать резервируемый бит/поле без нарушения CRC и обратной совместимости; если нужна миграция, явно спроектировать версию/откат, тесты чтения старого журнала и write/readback. Не стирать старые рекорды. Не выполнять запись при каждом кадре; только при изменении настройки.

## Архитектура
Game/domain публикует события ErrorOccurred/AnswerAccepted (или существующие эквиваленты), application управляет глобальной политикой mute и маршрутизацией; infrastructure реализует audio HAL, Windows simulator использует mock/null adapter. Не связывать игры напрямую с Pico SDK или GPIO. Один аудиосервис, без копирования логики между играми. Приоритет безопасности питания и кадров LCD выше звука.

## Тесты и приёмка
1. Unit/native: событие ошибки ровно один раз, ответ шара ровно один раз на принятый запрос, debounce, отсутствие звука при mute, настройка единая для всех игр, пиктограмма поглощает touch, звук прекращается при выключении.
2. Persistency: загрузка v3 и нового формата, CRC/sequence, реальный readback, сохранность всех старых результатов, переключение mute после reboot.
3. Simulator: 240×240 layout Rules каждой игры, иконка читаема, hitbox не конфликтует; аудио mock проверяет последовательность и длительность событий.
4. Firmware: native/Python, CI, UF2. Аппаратная прошивка только после разрешения и идентификации платы; перед записью backup обоих секторов, verify.
5. Физическая приёмка: пользователь подтверждает, что «кх» и «уоп» реально слышны, **значительно тише прежнего писка** и не раздражают. До этого не считать SOUND готовым.

## Не менять
