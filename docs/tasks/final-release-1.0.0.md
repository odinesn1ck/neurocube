# NeuroCube — финализация релиза 1.0.0 и подготовка публичного репозитория

## Цель
Подготовить качественный воспроизводимый финальный релиз 1.0.0 на основе проверенной 0.3.5, **без новых функций и без переписывания архитектуры**. Пользователь утвердил лицензию собственного кода **MIT**. Репозиторий будет публичным, но изменение visibility и merge в main — только по отдельному явному разрешению пользователя.

## 0. Подготовка и разрешения
Синхронизировать codex/neurocube-mvp с сохранением незакоммиченных изменений. Изучить AGENTS.md, docs/documentation-policy.md, README.md, docs/product-vision.md, docs/architecture.md, docs/hardware.md, docs/build.md, docs/player-guide.md, docs/backlog.md, docs/progress.md, CHANGELOG.md, docs/evidence/simon-progressive-speed.md и актуальный код.
В начале запросить все предсказуемые разрешения на установку инструментов, сеть, CI, публикацию draft release и при необходимости безопасную прошивку. Не выполнять merge, изменение visibility, стирание flash, force push или публикацию персональных сведений без отдельного подтверждения.

## 1. Заморозка функциональности и регрессия
- Freeze features: не добавлять игры, новые звуки, настройки, переработку рекордов, 5 уровней лабиринта или иные возможности. Исправлять только подтверждённые блокирующие дефекты, по возможности минимальными патчами.
- Native suite, Python tests, архитектурные проверки, Markdown links, headless simulator, Windows simulator, ARM UF2, GitHub Actions.
- Повторно проверить Simon 32 раунда и скорость, Maze retry/new и касания, Commands swipe/gyro/touch, Magic Ball 24 пары, единый mute и аудиособытия, splash/QR, crawl/idle/wake, PWR shutdown, сохранение данных и батарейный latch.
- Убедиться, что debug injection отключён в production; журнал рекордов и reserved UF2 page защищены; стек/память в допустимых пределах. Записать результаты в evidence.
- Отдельный короткий физический чек-лист для пользователя: PWR off/on, работа без USB, splash/QR, несколько раундов Simon, новые звуки, лабиринт, Commands, Magic Ball, crawl и touch/PLUS wake. Не объявлять физическую приёмку по USB/framebuffer.

## 2. MIT и сторонние компоненты
- Создать/проверить корневой LICENSE с каноническим текстом MIT для **оригинального кода NeuroCube**, корректным годом и владельцем copyright на основе данных репозитория; если имя/правообладатель не подтверждены — запросить один раз, не выдумывать.
- Проверить все внешние библиотеки, SDK, встроенные ресурсы, шрифты, QR-генератор, аудиодрайвер, код Waveshare и любые скопированные фрагменты: происхождение, лицензии, обязательные notices/attribution и совместимость с публичным распространением. MIT проекта **не переопределяет** лицензии третьих лиц.
- Сохранить LICENSE/NOTICE/THIRD_PARTY_LICENSES при необходимости, проверить состав релизных архивов и исходных файлов.
- Не включать в публичный репозиторий проприетарные заводские firmware backups, чужие изображения/музыку, секреты, приватные диагностические дампы.

## 3. Аудит публичности и безопасности
- Проверить весь доступный git history и рабочее дерево (не только HEAD): токены GitHub/PAT, пароли, API keys, персональные данные, email, реальные serial, локальные пути/имена пользователей, firmware/flash dumps, резервные копии и бинарные артефакты. Не выводить найденные секреты в отчёт/логи. Оценить, какие сведения реально чувствительны, не считать любой serial секретом автоматически.
- Проверить .gitignore, CI workflow permissions и отсутствие write-токенов в файлах; GitHub release assets и attachments также проверить.
- Если секрет когда-либо попал в историю, остановить публикацию, предложить ротацию/отзыв и отдельный план очистки истории. Не выполнять destructive history rewrite самостоятельно.
- Отчёт Public Readiness: PASS/BLOCKED с перечнем проблем и безопасными рекомендациями.

## 4. Документация для нового разработчика и владельца
- README: стратегическое описание, понятный quick start, ссылки на сборку, hardware, architecture, player-guide, CONTRIBUTING, LICENSE. Без текущих дефектов и датированных P0.
- CONTRIBUTING.md: Windows bootstrap, native tests, simulator, UF2, безопасное добавление игры через GameRegistry, PR workflow, coding standards и запрет случайного стирания рекордов.
- docs/player-guide.md: короткая инструкция PWR (1.8 с -> «Выключаюсь»), PLUS, BOOT, стартовая заставка «Привет, Андрей», QR через касание, три игры, Magic Ball, единый звук/иконка, скринсейвер и пробуждение. Указать, что BOOT — сервисная кнопка, не игровая.
- docs/backlog.md: разделить открытые задачи и архив, убрать противоречивые статусы старых версий. docs/progress.md: актуальный статус 1.0.0 и ссылки на архивные evidence; CHANGELOG.md: выпуск 1.0.0 только после фактического релиза.
- Не менять продуктовый замысел без решения пользователя; не удалять первичные отчёты.

## 5. Версия и поставка
- Выявить все источники версии (CMake, headers, USB hello, docs, artifact naming), привести к 1.0.0 согласованно без ломания USB-протокола.
- Создать воспроизводимую production сборку UF2 и Windows simulator; release archive с LICENSE, third-party notices, README, player-guide, SHA256/manifest. Проверить скачивание и побайтное совпадение UF2 с исходным артефактом.
- Перед flash: отдельное разрешение, идентификация платы serial/topology, backup journal 8192 байт вне Git, verify записи и records/settings readback. Если пользователь не разрешил — оставить статус COMPILED_ONLY.
- Подготовить release notes с функциями и честными ограничениями. Draft release/tag 1.0.0 можно подготовить после разрешения, но **не публиковать окончательный стабильный релиз до физической приёмки и согласования**.

## 6. GitHub
- Работать в codex/neurocube-mvp, небольшие коммиты, push, обновить существующий PR #1; без force push, без merge в main.
- Не переводить репозиторий в Public самостоятельно. Предоставить инструкцию владельцу и перечень проверок перед переключением.
- Итоговый отчёт: source commit, тесты, CI links, release assets и SHA256, лицензии, Public Readiness, физический чек-лист, блокеры и точные действия владельца для окончательной публикации.

## Acceptance
Версия 1.0.0 подготовлена воспроизводимо; MIT корректна, лицензии третьих лиц соблюдены; нет неразрешённых проблем публичности; рекорды не затронуты; документация позволяет новому агенту продолжить проект; релиз не объявлен полностью проверенным до физического подтверждения.
