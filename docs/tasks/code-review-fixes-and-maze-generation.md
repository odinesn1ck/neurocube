## Главный продуктовый принцип
**Генерация новых лабиринтов — обязательная механика, не устранять её.** «Заново» повторяет ту же карту с теми же настройками и seed; отдельная явно названная команда «Новый лабиринт» создаёт новую карту выбранной сложности. «Следующая игра» продолжает переключать игры. Никаких скрытых изменений карты при рестарте.

## P0 — GAME-002a: управляемая генерация лабиринтов
1. Изучить App::launch/restart, MazeGame::start, make_maze и формат рекордов. Сейчас вариант карты меняется на каждом launch и привязан к 3 вариантам/сложность.
2. Развести действия: retry_same_maze (сохранить seed, геометрию, лимит касаний, вернуть шар в старт); new_maze (новый seed и генерация); next_game (сменить режим).
3. Добавить сенсорную кнопку «Новый лабиринт» на подходящий экран (setup/result/pause), не перекрывая существующие глобальные кнопки; обеспечить очевидность различия с «Заново». Учитывать экран 240×240 и hitboxes.
4. Сохранить детерминированность по seed: одинаковые параметры -> идентичная карта, разные seed -> разнообразие, гарантированная проходимость. На первом этапе допустимо оставить существующие 9 карт только как fallback, но приоритет — генератор с расширенным пространством seed без жёсткого ограничения тремя вариантами. Проверить размеры массивов, число стен, проходимость и невозможность выхода за пределы памяти на всех сложностях.
5. Рекорды: не смешивать несопоставимые карты. Не менять без миграции существующий v3 журнал, адреса двух flash-секторов и реальные результаты. Для произвольных seed предложить ограниченное хранилище рекордов отдельных карт (например последние/избранные) и агрегаты по сложности; при нехватке времени не вводить рискованную миграцию, можно показывать результат попытки без глобального «рекорда» для новых seed. Обязательно документировать честную семантику.
6. Тесты: retry сохраняет seed/карту и настройки; new_maze меняет seed и (практически всегда) карту; генерация детерминирована; сотни/тысячи seed проверяются на проходимость, wall_count и границы; рекорды разных карт не смешиваются; сенсорные hitboxes работают.

## P0 — GAME-003a: «Лови команду»
Сейчас круг перемещается к фиксированной точке после правильного ответа, а не от наклона во время выполнения; метка вращается постоянно; при «Вниз» возможное наложение на подсказку. Реализовать управление кругом в процессе команды с понятной визуальной реакцией на наклон/поворот/touch, не ломая распознавание правильного действия. Ограничить игровую область так, чтобы круг не перекрывал подсказку и таймер. Тестировать изменение позиции до завершения команды, вращение только при реальном повороте, layout всех шести команд.

## P0 — UX-003: чувствительность
Исправить цикл значений 0.8 -> 1.0 -> 1.5 -> 0.8 с корректным восстановлением из Flash и отображением. Не изменять калибровку. Тестировать полный цикл и сохранение.

## P1 — POWER-001a: повторный gpio_init
В main вызывается Board::hold_power() до stdio; затем Board::init() повторно вызывает hold_power(), внутри output(28,true) снова gpio_init(28). Убрать ненужную повторную инициализацию **только после проверки Pico SDK и безопасного порядка**; сохранить BAT_EN GPIO28 непрерывно HIGH, особенно при работе от аккумулятора. Не менять GPIO24/17/29, зарядку, схему, OTP. Не утверждать, что повторный gpio_init уже доказал реальный сбой питания. При сомнении — оставить аппаратный код без изменений, зафиксировать обоснование и физическую проверку.

## P1 — контакты стен
Сейчас физическая коллизия с radius=4, а учёт касаний дополнительно использует radius=5.5. Согласовать смысл штрафного касания с фактическим контактом, отделить предупреждающую близость от удара. Одно непрерывное касание = одно событие, hysteresis/rearm. Тесты: приближение без касания, столкновение, удержание, отход и повторный контакт.

## P2 — пагинация меню
При более чем четырёх играх индекс (y-43)/39 может выбрать невидимую кнопку следующей страницы. Использовать hitbox только реально отрисованных кнопок; тестировать 5+ игр, зазоры и границы страниц.

## Требования к процессу
- Сохранять Clean Architecture; игры без Pico SDK, ввод/навигация через application.
- Не менять 24 пары Magic Ball, «Нужна перезагрузка», «Привет, Андрей», QR, скринсейвер и каталог трёх сетов.
- Сначала тесты в native/simulator, затем RP2350 build. Если ранее дано разрешение на flash, использовать только идентифицированную плату с verify, не стирать рекорды и backup. Проверить холодный запуск/автономность только с участием пользователя; USB smoke не равен физической проверке.
- Обновить docs/backlog.md, docs/progress.md, CHANGELOG.md, docs/player-guide.md; долгосрочную механику генерации при необходимости уточнить в docs/product-vision.md без датированных багов.
- Коммиты в codex/neurocube-mvp, push и обновление PR; без force push и merge.
- В отчёте: фактически изменённые файлы, tests/build, семантика seed и рекордов, UF2, аппаратные риски и короткий ручной чек-лист.

## Критерии приёмки
«Заново» воспроизводит текущий лабиринт; «Новый лабиринт» создаёт другой проходимый лабиринт; игрок видит различие; рекорды корректны. «Лови команду» имеет отзывчивый круг; чувствительность циклически выбирает три значения; касания стен считаются честно; пагинация не открывает невидимые игры; BAT_EN остаётся HIGH.
