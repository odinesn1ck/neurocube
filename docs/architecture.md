# Архитектура NeuroCube

Игровые правила и сценарии не зависят от Pico SDK. Один C++17 core собирается для Windows и RP2350. Внешние адаптеры передают значения InputFrame и реализуют порты Renderer и RecordStore.

```text
infrastructure -> application -> domain
presentation -----------------> domain
games ------------------------> domain
composition registry ---------> application + games
```

## Слои

- `include/neurocube/domain.hpp`, `src/domain`: InputFrame, Actions, Result, Metadata, Game, Renderer, RecordStore, генератор и формат рекордов.
- `src/application`: App выполняет роль GameManager и SessionManager, маршрутизирует ввод и навигацию; ButtonRecognizer устраняет дребезг и различает короткое/длинное нажатие; GestureRecognizer фильтрует IMU, распознаёт наклон, поворот и встряхивание. GameRegistry содержит статический набор игр.
- `src/games`: независимые реализации правил, использующие domain и переносимые помощники рисования ui.hpp; application и аппаратура не импортируются. Их единственный внешний эффект — вызов Renderer при render.
- `src/presentation`: RGB565 framebuffer, геометрия и UTF-8 текст. Русский bitmap-шрифт включён в исходники и не требует файловой системы.
- `src/infrastructure`: Waveshare HAL, FlashStore, CDC-протокол, firmware entry point и Windows-симулятор.
- `tools/neurocube.py`: отдельный процесс Hardware Bridge; блокировка одного владельца, USB-идентичность, сборка, диагностика и flash pipeline.

Связь игры с интерфейсом выполняется через Game: metadata, start, update, render, pause, resume, stop, result. Динамические плагины и контейнер DI не используются. Встроенная регистрация — composition root в src/application/registry.cpp; приложение может получить другой реестр в конструкторе, как делают тесты.

## Ввод и жизненный цикл

InputFrame содержит физические значения в g и градусах/с, координаты touch и события кнопки. GestureRecognizer выдаёт Actions. Фильтр зависит от dt, наклон имеет порог и возврат в нейтраль, встряхивание — cooldown 1,2 с. В меню встряхивание игнорируется; в играх перезапускает попытку; в Magic Ball выбирает ответ.

Приоритет: длинная физическая кнопка, короткая кнопка, меню/настройки, глобальная сенсорная панель, правила/пауза/результат, встряхивание, игровой ввод. Событие панели не попадает в игру. Пауза прекращает update игры, возобновление сбрасывает распознаватель жестов. Поворот — скорость вокруг оси Z; порог 160 градусов/с, подтверждение не менее 60 мс и cooldown 0,65 с. Commands отдельно допускает сопутствующий наклон меньше 0.65 в Actions при ожидаемом повороте и поворот меньше 240 градусов/с при ожидаемом наклоне. Сенсорный поворот обрабатывается игровой механикой, аппаратные пороги от него не зависят.

## Рекорды

Централизованная таблица 3 игры × 3 сложности. Сохраняется только улучшение при завершении или уходе из игры, а не каждый кадр. Формат версии 3 (читает также версии 1 и 2): magic, версия, sequence, little-endian значения, CRC32; запись 512 байт.

На плате чередуются два сектора по 4 КиБ в конце 16 МиБ Flash. Сначала записывается неактивный сектор, затем проверяется CRC и содержимое. Предыдущая копия остаётся действительной при неполной новой записи. При загрузке выбирается валидная копия с более новым sequence с учётом переполнения. Запись идёт через pico_flash_safe_execute при работе на одном ядре. UF2-валидатор запрещает пересечение с рекордами. Чувствительность и калибровка сохраняются в v3. Legacy best остаётся на прежнем месте, новая таблица лабиринта разделена по геометрии, варианту карты и лимиту контактов; старый результат не смешивается с новой физикой.

## Добавление игры

1. Реализовать Game, используя только domain и стандартную библиотеку. Никаких GPIO или SDK в модуле.
2. Добавить экземпляр и метаданные в статическую регистрацию и увеличить count реестра. Зарезервировано 16 слотов; порядок существующих игр сохранять, поскольку он определяет слоты рекордов. Меню автоматически листает страницы по четыре игры.
3. Добавить переносимые тесты правил, завершения, паузы и ввода. Ядро App менять для новой механики не требуется.
4. Проверить UI на 240×240 и отдельную строку с правилами, затем выполнить аппаратную приёмку.

В формате рекордов зарезервированы 16 слотов, три сложности на слот; сейчас используются три. Magic Ball помечен метаданными как режим без рекордов и без перезапуска встряхиванием. Реестр статический; одновременные App в production не поддерживаются общей default_registry, тесты могут передать отдельные экземпляры.

## Idle и управление дисплеем

Переносимый `IdleController` отвечает за таймер, фазы и поглощение wake-события. App сохраняет экран возврата и передаёт только запрос яркости/idle в composition root. Отдельный `DisplayPower` реализует PWM GPIO13; игровой модуль не знает о подсветке или питании. Эпизоды — domain-данные, проекция и bitmap-рендер — presentation. Подробные переходы, границы ресурсов и fallback: [screensaver](screensaver.md).

## Бюджет стека RP2350

Core0 резервирует 4096 байт в SCRATCH_Y. App, строка передачи framebuffer и рабочее место FlashStore живут в статической памяти; запись обслуживается одним foreground-владельцем, не из IRQ и не с core1. Проверка записи сравнивает все 512 байт с подготовленной CRC-записью. ARM-сборка создаёт `.su` через `-fstack-usage` для аудита вложенных вызовов; это не измерение полного динамического high-water mark.

## Процедурные лабиринты

App хранит отдельный maze_seed в RAM. retry_same_maze повторяет его, new_maze выбирает следующий ненулевой 32-битный seed; переход к другой игре не меняет текущую карту. Сложность определяет сетку 5×4, 6×5 или 7×5. DFS выбирает корень и проходы из seed, строит связное дерево из N−1 рёбер. Максимум 35 клеток и 28 стен; массивы ограничены 35/96 элементами, куча и рекурсия не используются. Начало/цель фиксированы, коридоры допускают шар радиуса 4. Разные seed могут совпасть по геометрии, особенно на малой сетке; это не ограниченный набор заранее заданных карт.

Процедурный режим не пишет ни legacy best, ни maze_best: текущий счёт не является глобальным рекордом. Формат v3 и flash-адреса сохранены. Будущий формат может хранить ограниченные последние/избранные карты с ключом (версия генератора, seed, геометрия, лимит), но требует отдельного проектирования и миграции. Агрегаты по сложности следует показывать отдельно от рекорда карты.

Контакт возникает только при блокировке перемещения радиусом 4. Радиус 5.5 используется исключительно для выхода из контакта: после отдаления на 140 мс штраф снова разрешён. Actions передаёт непрерывную угловую скорость отдельно от дискретного события twist; Commands визуально реагирует на неё и наклон до завершения команды.
