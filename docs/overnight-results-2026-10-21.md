## Реализованный результат

Clean Architecture: переносимые domain, application, games и presentation, аппаратные зависимости только в infrastructure. Один игровой core используется прошивкой и Windows-симулятором. Статический реестр рассчитан на 16 режимов, меню листается по четыре; добавление игры не требует изменения App. Формат рекордов резервирует 16 слотов × 3 сложности.

Доступны три игры: «Повтори ритм», «Лабиринт», «Лови команду»; отдельно — «Шар ответов». Есть правила, русский шрифт, три сложности, пауза, рестарт, следующая игра, меню, калибровка и чувствительность. Глобальные команды продублированы touch. Встряхивание перезапускает обычную игру, выдаёт новый ответ в Magic Ball и игнорируется в меню. Двойное встряхивание не используется.

Рекорды записываются централизованно при улучшении результата, а не каждый кадр. Два сектора, CRC32, sequence и выбор действительной копии обеспечивают восстановление после повреждения одной записи. Само отключение питания в момент записи аппаратно не имитировалось.

Hardware Bridge реализует detect, info, logs, build, flash, selftest, records и screenshot. Он проверяет USB-идентичность, блокирует второго владельца, валидирует UF2, повторно сопоставляет плату после BOOTSEL, выполняет запись с verify и проверяет runtime handshake. COM-порт не зафиксирован в коде.

## Исправленные проблемы

- Медленное побайтовое чтение большого framebuffer приводило к тайм-ауту. Bridge теперь читает буферами, firmware формирует строку целиком. Финальный capture занял около 0,66 секунды.
- Служебный UF2-блок errata RP2350-E10 по умолчанию находился около журнала рекордов. Он перенесён на отдельную страницу, а валидатор проверяет его формат и запрещает пересечение программы с этой страницей и рекордами.
- После начальной незавершённой распаковки toolchain старый CMake cache сохранил неверные C release flags. Сборка использует --fresh; после исправления два независимых UF2 совпали.
- Расширяемость реестра, восстановление повреждённой записи и антидребезг дополнительно покрыты переносимыми тестами.

## Что не завершено

GitHub отказал в push файла .github/workflows/build.yml: PAT не имеет workflow scope. Для продолжения код опубликован, CI-шаблон сохранён в [docs/ci/build.yml](ci/build.yml), а бинарники опубликованы файлами предварительного релиза. CI не запускался и не отмечается успешным. Для включения нужен Workflows: Read and write у fine-grained PAT либо workflow scope у classic PAT, затем перенос YAML в .github/workflows/build.yml.

P1/P2 не реализованы: звук, энергосбережение, дополнительные девять игр, достижения и расширенная статистика. Калибровка, чувствительность и выбор сложности действуют до перезапуска; постоянно сохраняются рекорды. В GUI симулятора ввод мышью и клавиатурой ещё требует ручной проверки. Возможность автономной работы может потребовать отдельного согласованного изменения удержания питания, поскольку текущая прошивка намеренно не управляет BAT_EN.
